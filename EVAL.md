# Preflight offline evaluation

Generated by `python -m preflight.eval` from `artifacts/eval.json`. Do not edit numbers by hand.

Seed: **2026**. Cases: **480**. All runs use FakeExtractor, in-memory SQLite and real PDF ingestion/citation validation. No network or trained model is used.

## Metric definitions

A positive is REVIEW or BLOCK. A false negative is a malicious case receiving PASS. Legitimate reviews, including prudent reviews for missing data, count as false positives (workflow friction). Expected verdicts encode ground-truth intent; a prudent REVIEW can disagree with PASS ground truth without being a software defect.

Each attack row compares that attack against the same complete legitimate pool. Precision is TP/(TP+all legitimate FP); FPR uses that pool. Benign rows use only their own stratum. Recall is undefined; precision is zero when positive predictions exist and undefined otherwise. The reused negative pool means rows must not be added together. All intervals are Wilson 95%; counts and denominators are shown.

## Extraction-noise and miss analysis

Bank-change attacks deliberately include dropped bank fields and wrong-but-cited superseded accounts. Inflated invoices also have a separate wrong_cited_amount stratum selecting a real, coherent historical quote. OCR substitutions on legitimate invoices and missing totals measure false-review friction. These errors are injected in the extractor fixture, not in policy labels.

### False negatives (30)

- `bank_change/000`: intended BLOCK, got **PASS**; noise `wrong_but_cited_bank`. Extractor selected the superseded approved account; citation presence cannot bind payment intent.
- `bank_change/001`: intended BLOCK, got **PASS**; noise `dropped_bank`. Dropped payment fields leave bank change unverifiable; other checks can still pass.
- `wrong_cited_amount/000`: intended REVIEW, got **PASS**; noise `wrong_but_cited_amount`. Extractor selected a coherent historical quote instead of the inflated current amount.

### False positives (120)

- `large_oneoff/000`: intended PASS, got **REVIEW**; noise `none`. A legitimate one-off purchase is indistinguishable from inflation using amount history alone.
- `constant_changed/000`: intended PASS, got **REVIEW**; noise `none`. A small legitimate increase triggers the conservative zero-MAD rule.
- `dropped_fields/000`: intended PASS, got **REVIEW**; noise `dropped_total`. Missing total correctly forces review but counts as friction on a legitimate invoice.
- `ocr_swap/000`: intended PASS, got **REVIEW**; noise `OCR character substitution in GSTIN`. OCR-style identifier substitution produces a false identifier warning.
- `legitimate_reply_service/000`: intended PASS, got **REVIEW**; noise `none`. Legitimate external reply routing triggers the same domain-mismatch signal as hijacking.

## Honest limitations

- Synthetic PDFs and fixture extractions measure deterministic triage, not real-world fraud accuracy or live-model robustness.
- Wrong-but-validly-cited bank and amount values can pass when the model chooses a superseded account or coherent historical quote. Text presence does not establish semantic association.
- Dropped payment fields can leave bank change unverifiable while other checks still permit PASS. The gap stays visible, but PASS must not be treated as payment authorization.
- Sender display-name/domain and external Reply-To heuristics cannot establish intent. Legitimate routing services can be false positives; unrelated attacker domains may evade distance checks.
- Uploaded Authentication-Results are untrusted. Passing headers never establish authenticated sender identity; no receiver trust integration is provided.
- Median/MAD flags legitimate large one-off invoices. Zero-MAD handling flags even small legitimate increases. Neither method proves fraud.
- No OCR: image-only evidence returns REVIEW. Identifier syntax/checksums do not establish registration, ownership or bank existence.
- Vendor matching uses an explicit selection or exact extracted name. No authenticated vendor identity, payment execution or multi-user access control exists.
- Native document parsers run in-process with bounded inputs, not an isolated CPU/memory sandbox. Local reports retain sensitive evidence on disk without encryption.
- The corpus uses reserved example domains and one vendor template with varied amounts/noise. Equal strata do not estimate production prevalence. Wilson intervals assume independent trials; shared templates violate that assumption, so intervals are descriptive only.
- The regression gate uses point estimates and the same synthetic seed used for initial calibration. It is a regression alarm, not a held-out validation claim.
